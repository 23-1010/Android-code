## 一、 项目概述

本项目为一款名为"慕陶心理"的微信小程序，旨在为用户提供便捷的心理健康服务与专业的心理量表自测功能。系统采用业界主流的**前后端分离架构**进行开发。

- **前端（客户端）：** 采用微信小程序原生技术栈（WXML, WXSS, TypeScript）结合 ECharts 图表库进行开发，实现了跨平台的移动端用户交互。前端通过自定义 TabBar 实现了学生端与教师端的差异化导航。

- **后端（服务端）：** 采用 Java 语言与 Spring Boot 4.0.7 框架搭建，基于标准的 MVC（Model-View-Controller）三层架构（Controller → Mapper → Entity）处理复杂的业务逻辑。数据交互通过 MyBatis 注解式 SQL 映射实现。

- **数据持久化：** 采用 MySQL 8.0 关系型数据库进行数据的持久化存储，设计了 7 张核心数据表，涵盖用户、咨询师、测评题库、测评记录、预约、绑定关系及绑定申请等完整业务域。

### 项目技术栈总览

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | 微信小程序原生 + TypeScript | WXML/WXSS 模板 + 强类型逻辑 |
| 图表可视化 | ECharts (ec-canvas) | 雷达图、进度条可视化 |
| 后端框架 | Spring Boot 4.0.7 | RESTful API |
| ORM | MyBatis (注解式) | 直接 SQL 映射 |
| 数据库 | MySQL 8.0 | utf8mb4 字符集 |
| 通信 | HTTPS + ngrok 内网穿透 | 前后端分离调试 |

## 二、 需求分析与功能设计

系统为满足不同角色的使用需求，设计了基于角色的访问控制（RBAC）体系，区分"学生/普通用户"与"咨询师/教师"两种权限。学生端仅显示「主页」和「我的」两个 Tab，教师端额外拥有「后台」和「预约」Tab。

### 1. 核心功能模块划分

系统共设计 12 个前端页面和 10 个后端 Controller，覆盖登录鉴权、主页展示、咨询师管理、心理测评、数据后台、学生管理、师生绑定、个人资料及预约等完整业务场景。下面逐模块详细阐述。

#### 1.1 微信静默登录与角色初始化

**功能描述：** 用户打开小程序后无需手动输入账号密码，系统自动完成身份认证。前端调用微信原生 `wx.login()` 接口获取临时授权码（code），后端携带该 code 向腾讯微信服务器发起 HTTPS 请求，换取当前用户的唯一标识 `openid`。若该 openid 在数据库中不存在，则自动创建新用户记录（默认角色为 `student`）；若已存在则直接返回用户身份、角色及关联的咨询师编号（counselorId）。系统同时设计了开发模式兜底机制——当后端接口不可达时，前端自动写入预设的测试教师身份，确保开发调试不受阻塞。

**涉及文件：**

| 端 | 文件 | 作用 |
|----|------|------|
| 前端 | `miniprogram/app.ts` | `onLaunch` 生命周期 → 同步写入默认身份兜底 → 异步调用 `wx.login()` → 调后端 `/api/wx/login` → 更新 Storage |
| 前端 | `miniprogram/utils/util.ts` | 封装 `wx.request`，统一添加 `ngrok-skip-browser-warning` 头 |
| 后端 | `controller/LoginController.java` | `POST /api/wx/login` — 接收 code → 拼接请求 URL → 调微信 `jscode2session` → 解析 openid → 查/插 `users` 表 → 返回 userInfo |
| 后端 | `mapper/SysUserMapper.java` | `getUserByOpenid`（按 openid 查用户）、`insertUser`（新建用户） |
| 后端 | `entity/SysUser.java` | users 表实体映射 |

#### 1.4 专业心理测评模块（核心难点）

**功能描述：** 本模块是项目中业务逻辑最复杂的子系统，实现了从量表选择 → 引导页 → 交互式答题 → 智能批卷计分 → 可视化报告 → PDF 导出的完整闭环。

**量表选择页**（assessment）：展示可用量表卡片列表（如"SCL-90 症状自评"、"SDS 抑郁自评"），每张卡片包含量表名称和简短说明，点击进入引导页。

**测评引导页**（assessmentIntro）：展示量表介绍、题目数量、预计耗时等信息，底部"开始测评"按钮。

**交互式答题页**（assessmentDo）：从后端获取的 JSON 题库中动态渲染题目。每题以独立白色卡片呈现，题号与题目文本顶部展示，选项以纵向列表排列。用户点击选项后该选项高亮（蓝色边框），再次点击其他选项自动切换。所有题目采用 `<scroll-view>` 包裹，支持流畅滚动。提交时弹出确认对话框"是否确认交卷？"，确认后收集全部答题数据（题目 ID → 用户所选分值映射）通过 POST 请求发送到后端。

**后端计分引擎**（ResultController）：接收用户答卷后，从 `assessment` 表读取该量表的完整 JSON 题库结构。通过 Jackson `ObjectMapper` 解析嵌套 JSON，遍历题目节点统计原始总分。随后根据 `scaleType` 字段进行策略分发——SCL-90 走多维度算法（按 9 大因子维度归类统计，计算各维度均分与四级评级，判定阳性/阴性），SDS 走标准分换算（原始总分 ×1.25，对照阈值判定轻度/中度/重度抑郁）。计分完成后将完整报告 JSON 写入 `assessment_records` 表持久化。

**可视化报告页**（assessmentResult）：从后端返回的报告 JSON 中提取数据，分区域渲染——顶部总分与评级概览（动态变色：正常=绿、轻度=黄、中度=橙、重度=红）、各维度得分进度条（百分比条 + 评级文字）、ECharts 雷达图（9 维因子多边形可视化）、每条维度的个性化医学建议（读取 TypeScript 端内置的 9 因子 × 4 级别 = 36 条文案库）。页面底部提供"返回首页"和"导出 PDF 报告"两个按钮。

**PDF 导出**：前端将报告数据和填写人信息 POST 到后端 `/api/print/report`，后端生成 PDF 二进制流返回，前端通过 `wx.getFileSystemManager()` 写入本地文件，再调用 `wx.openDocument()` 打开预览。

#### 1.7 师生绑定码系统

**功能描述：** 实现了一套完整的师生账号绑定流程，取代传统的"管理员手动分配"模式。**绑定码生成**：每位咨询师在 `counselors` 表中维护一个 4 位唯一绑定码，首次获取时由后端随机生成（范围 1000-9999，自动排除 1234、4321 等顺序数字），写入数据库后持久化。教师在"我的"页面查看自己的绑定码，并告知学生。**学生申请**：学生在"我的"页面输入 4 位绑定码，点击"绑定老师"按钮，后端根据绑定码查找对应咨询师，校验是否已有待处理申请、是否已绑定其他老师，通过后创建一条 `status = 'pending'` 的申请记录。**教师审批**：教师在"我的"页面看到"我的消息"区域（仅在有未处理申请时显示），每条申请展示学生姓名和申请时间，配有绿色"通过"和灰色"拒绝"两个操作按钮。通过后自动向 `teacher_students` 表写入绑定关系，被拒绝的学生可重新申请。绑定后，学生端"我的老师"区域展示老师头像、姓名、头衔以及绿色"已绑定"标签。

## 三、 数据库设计与持久化方案

为了满足课程要求中"对数据的持久化保存方式：使用数据库"的考核点，本项目在 MySQL `mutao_base` 数据库中设计了高度解耦的关系型数据表结构。以下为全部核心数据表设计：

| 数据表名称 | 核心字段 | 作用说明 |
|-----------|---------|---------|
| **users** | id, openid, nickname, real_name, gender, birth_date, avatar, role, counselor_id | 存储用户的微信身份、角色权限（student/teacher/counselor）及个人资料 |
| **counselors** | id, user_id, name, title, avatar, short_desc, full_desc, specialties, phone, bind_code, status | 存储咨询师的详细信息、绑定码及在职状态 |
| **assessment** | id, title, scale_type, questions_json | 存放不同量表的元数据，题目与计分权重采用原生 JSON 格式灵活存储 |
| **assessment_records** | id, user_id, scale_type, scale_name, total_score, result_rating, detail_json, create_time | 永久记录用户每次交卷的得分、维度评级及完整报告 JSON |
| **appointments** | id, student_id, counselor_id, appointment_date, appointment_time, status, reason, teacher_notes | 预约记录管理 |
| **bind_requests** | id, student_id, counselor_id, status, create_time | 师生绑定申请流程，状态流转：pending → approved/rejected |
| **teacher_students** | id, teacher_id, student_id, notes | 老师-学生绑定关系及备注 |

### 数据库设计亮点

1. **JSON 灵活存储**：测评题库 (`questions_json`) 和测评结果 (`detail_json`) 采用 MySQL TEXT 字段存储 JSON，兼顾结构化查询与灵活扩展
2. **唯一约束防重**：`teacher_students` 表使用 `UNIQUE KEY uk_teacher_student (teacher_id, student_id)` 防止重复绑定
3. **兼容性迁移脚本**：通过存储过程 `add_column_if_not_exists` 实现幂等的增量列添加，避免重复执行报错
4. **外键逻辑关联**：`users.counselor_id` → `counselors.id`，`assessment_records.user_id` → `users.id`

### 1. 量表 JSON 动态解析与计分引擎 (后端)

为了应对 SCL-90 量表（9 大维度分别计算因子分与均分）与 SDS 量表（原始总分 ×1.25 换算标准分）等截然不同的计分规则，后端引入了"量表类型驱动（Type-Driven）"模式。通过 `scaleType` 字段动态分发计分策略，利用 Jackson `ObjectMapper` 解析复杂的嵌套 JSON 题库，实现了高度可扩展的智能批卷逻辑。

**核心代码：`ResultController.java` — 策略分发计分引擎**

```java
@PostMapping("/calculate")
public Map<String, Object> calculateScore(@RequestBody SubmitDto submitDto) {
    // 1. 从数据库读取量表元数据（含 JSON 题库结构）
    Assessment assessment = assessmentMapper.getAssessmentById(submitDto.getAssessmentId());
    ObjectMapper mapper = new ObjectMapper();
    JsonNode rootNode = mapper.readTree(assessment.getQuestionsJson());
    JsonNode questionsNode = rootNode.get("questions");

    // 2. 统计原始总分
    int totalRawScore = 0;
    for (JsonNode qNode : questionsNode) {
        String qId = qNode.get("id").asText();
        if (userAnswers.containsKey(qId)) {
            totalRawScore += userAnswers.get(qId);
        }
    }

    // 3. 【核心策略分发】根据量表类型走不同计分逻辑
    String scaleType = assessment.getScaleType();
    if ("SCL90".equals(scaleType)) {
        calculateSCL90(questionsNode, userAnswers, totalRawScore, finalResult);
    } else if ("SDS".equals(scaleType)) {
        calculateSDS(totalRawScore, finalResult);
    }

    // 4. 成绩入库：提取最终得分与评级写入 assessment_records 表
    recordMapper.insertRecord(userId, scaleType, scaleName, finalScore, finalRating, reportJson);
}
```

**SCL-90 多维度计分算法：**

```java
private void calculateSCL90(JsonNode questionsNode, Map<String, Integer> userAnswers,
                             int totalScore, Map<String, Object> finalResult) {
    // 按维度归类统计：躯体化、强迫、人际敏感、抑郁、焦虑等 9 大因子
    Map<String, Double> dimTotalScores = new HashMap<>();
    Map<String, Integer> dimCounts = new HashMap<>();

    for (JsonNode qNode : questionsNode) {
        String dimension = qNode.get("dimension").asText();
        int score = userAnswers.get(qNode.get("id").asText());
        dimTotalScores.put(dimension, dimTotalScores.getOrDefault(dimension, 0.0) + score);
        dimCounts.put(dimension, dimCounts.getOrDefault(dimension, 0) + 1);
    }

    // 计算各维度均分与四级评级
    for (String dim : dimTotalScores.keySet()) {
        double avg = dimTotalScores.get(dim) / dimCounts.get(dim);
        dimData.put("rating", getSCL90Rating(avg));  // 正常/轻度/中度/重度
    }

    // 阳性判定：总分 > 160 或阳性项目数 > 43
    String isPositive = (totalScore > 160 || positiveCount > 43) ? "阳性" : "阴性";
}
```

### 2. 测评结果页 ECharts 雷达图渲染 (前端)

针对 SCL-90 的多维度心理测量结果，小程序前端集成了百度 ECharts 组件（`ec-canvas`）。在页面加载时读取后端返回的 9 维因子分数数组，动态映射并注入到 Radar Chart 的 `option` 配置项，直观展示各项心理指标的强弱分布。

**核心代码：`assessmentResult.ts` — 雷达图初始化**

```typescript
import * as echarts from '../../components/ec-canvas/echarts';

initRadarChart() {
    const report = this.data.report;
    const indicatorArr: any[] = [];
    const dataValues: number[] = [];

    // 将 9 大维度映射为雷达图指标
    report.dimensions.forEach((dim: any) => {
        indicatorArr.push({ name: dim.name, max: 5 });   // 5 级量表
        dataValues.push(dim.avg);                          // 维度均分
    });

    this.ecComponent.init((canvas, width, height, dpr) => {
        const chart = echarts.init(canvas, null, { width, height, devicePixelRatio: dpr });
        chart.setOption({
            radar: {
                indicator: indicatorArr,
                shape: 'circle',
                splitNumber: 5,
                name: { textStyle: { color: '#555', fontSize: 11 } }
            },
            series: [{
                type: 'radar',
                data: [{ value: dataValues, name: '均分',
                    areaStyle: { color: 'rgba(24,144,255, 0.3)' } }]
            }]
        });
        return chart;
    });
}
```
